# B2/B3 v3 输出格式协议

本轮只修订输出说明，不改数据、gold、split、C 校验规则和评分函数。已知 v2 B3 的 8 条失败中，7 条把步骤独立信心写成互斥下一步分布，另 1 条 Q 分布总和为 0.99；历史原始输出和 v2 聚合结果保留。

## 在重新调用前固定的程序

1. B2/B3 共享 `canonical-label-v3`：明确下一步分布以恢复为条件、各候选互斥，补充抽象两选项的合法/非法示例；每个状态因子的分布单独求和。示例不含实际样本答案。
2. 要求输出前检查所有分布总和（容差沿用 C 的 1e-6）。不确定时，步骤分布可为 null，状态分布可省略；不能用空分布代替恢复判断或步骤决定。评测缺失概率的覆盖率，不能将缺失概率当成校准良好。
3. 先在 dev 的全部 52 条上检查 B3 输出合法性，固定协议后再完整评测 test 的 B2/B3 各 52 条；不只补考 8 条失败，不按测试成绩选择结果。如果 dev 还有格式错误，暂停 test，报告原因；不自动反复改提示刷分。
4. 使用相同 deepseek-flash、temperature=0、thinking=disabled、单调用输出上限 4096；单样本并发，dev 新增已知 token 阈值 250000，test 阈值 400000。达到阈值后不再启动下一条，最后一条可能使总量超出阈值；失败调用 usage 可能缺失，均非账单硬限额。402 立即停止，不自动重试格式错误。
5. 不事后归一化旧的独立信心，不将它们冒充模型原本给出的概率。新版本独立命名保存，v2 结果保持历史记录。格式通过不等于答案正确，准确率没有预设提升目标。

## 结果适用范围

这是已暴露的脚本构造 P0 v0.3 上的一次新协议评测，不是新盲测，也不是算法能力提升的因果实验。B3 的结构化分析提示不变；B2 使用相同输出合同，便于比较。概率是模型自报，未做独立校准。
