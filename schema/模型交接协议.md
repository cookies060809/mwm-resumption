# 基线评测引擎输入输出协议（工程草案）

本文描述 `mwm_eval` 的独立工程协议。仓库已有 `p0_record.schema.json` 与 `data/p0/p0_samples.json`；它们保持原样，尚未映射到本文格式。此草案不替代 B 的正式 P0 规范，映射及语义变更需按仓库协作规范评审。

版本：`c-evaluation-draft-1`；日期：2026-10-19。对应可执行检查器为 `mwm_eval/schema.py`。这是 C 为接入和测试准备的工程协议；B 的正式 schema、事件词表及标注手册交付后，需要三人确认映射并锁定新版本，不能默默改字段。

## 1. 输入、答案、模型输出分开

交付两个 UTF-8 JSONL 文件，每行一个 JSON 对象：`inputs.jsonl` 为记录，`labels.jsonl` 为事后标注。文件行顺序可以不同，以唯一 `sample_id` 一一对应。样本记录外层元数据供划分和统计；模型的 `predict` **只接收其中的 observation**。

输入记录必须恰好具有以下字段：

| 字段 | 取值和用途 |
|---|---|
| `sample_id` | 非空唯一字符串；不交给模型 |
| `base_story_id` | 基础故事家族；同族变体不得跨 split |
| `person_id` | 人物分组；P1 应使用经授权的匿名 ID |
| `task_family` | 任务族分组，用于划分和泛化审计 |
| `domain` | 场景域分组 |
| `split` | `train / dev / calibration / test` |
| `purpose` | 非空用途说明；合成工程夹具必须用 `synthetic_integration_fixture` |
| `observation` | 下述截止观测对象，禁止 gold、split、家族 ID 或未来事件 |

单次评价只包含一种 `dataset_layer`：正式脚本 `P0`、真实行为 `P1` 或工程 `integration_fixture`。夹具的用途标记必须与其 layer 对应，不能把夹具改名当成正式 P0/P1。

## 2. observation

对象必须恰好具有 `target_person、goal_id、task_steps、task_graph、cutoff、horizon、events` 七个字段。

- `target_person`、`goal_id`：非空字符串。
- `task_steps`：非空、无重复的步骤 ID 字符串列表。
- `task_graph`：恰含 `nodes` 与 `edges`。nodes 与 task_steps 集合一致；edges 是 `[前置步骤, 后继步骤]` 的列表，不得重复、自环或形成有向环。列表顺序不是隐含依赖，依赖以 edges 为准。
- `cutoff`：有限数值时间；所有 events 的 time 必须有序且不超过 cutoff。
- `horizon`：恰含 `type` 和 `value`。type 为 `decision_opportunities` 时 value 必须为正整数；为 `seconds` 时为有限正数。时长单位和定义须写入数据卡并在各 split 一致。
- `events`：列表，可为空；每个事件遵循下一节。

例：

```json
{
  "target_person": "person_01",
  "goal_id": "order_17",
  "task_steps": ["pack", "print", "handover"],
  "task_graph": {"nodes": ["pack", "print", "handover"], "edges": [["pack", "print"], ["print", "handover"]]},
  "cutoff": 300,
  "horizon": {"type": "decision_opportunities", "value": 3},
  "events": []
}
```

## 3. 事件字段与接触证据

每条事件必须具有 `event_id、time、actor、event_type、goal_id、step_id、world_effect、observer_evidence、person_access_evidence、source、certainty`。仅允许额外的 `action_status` 与 `semantic`。

| 字段 | 工程约束 |
|---|---|
| `event_id` | 本 observation 中唯一非空字符串 |
| `time` | 有序有限数值，`time <= cutoff` |
| `actor`、`event_type`、`observer_evidence`、`source` | 非空字符串；类型词表仍需 B 定稿 |
| `goal_id`、`step_id` | 非空字符串或 null；原目标动作不能引用不存在的步骤 |
| `world_effect` | 字符串、对象或 null；客观事实，不能把它当成人物已知 |
| `person_access_evidence` | 恰含 status 与 understood；status 为 `ACCESSED / NOT_ACCESSED / UNCERTAIN`，understood 为 true、false 或 null |
| `certainty` | `[0,1]` 内有限数值，指证据可信度，不是恢复概率 |
| `action_status` | event_type=`task_action` 时必须为 `in_progress / completed`，同时必须给 goal_id 和 step_id |

`semantic` 为可选对象，仅允许以下键：

```text
kind, value, belief, reference_event_id, interpretation, step_id,
demand, demand_level, interruption_duration, goal_priority, reason,
completed_steps, parent_goal_id, task_completed, interrupting_goal_id
```

`reference_event_id` 必须指向本 observation 中更早的事件。semantic 是从截止证据可得到的事件内容，**不是 state_labels 的拷贝**。例如 notification 的内容、明确误读和中断负荷可以写在这里；真实心理状态没有证据就不得添加。

本地参考基线使用 `semantic.kind`，缺省回退到 event_type。已适配的常见 kind 有 `goal_started、goal_suspended、goal_abandoned、goal_completed、task_action、step_completed、cancellation、fulfillment、resource_blocked、resource_ready、notification_understood、commitment_resume、interruption_started、interruption_ended`。`notification_understood` 的 value 表达通知内容，`interpretation="defer"` 表达有证据的暂缓误读。B 采用其他词表时先做显式映射，不能只通过 JSON 校验就认为基线理解了事件。

## 4. labels.jsonl

必需字段为 `sample_id、dataset_layer、resume_label、resume_step、state_labels、state_evidence、window_complete`；可选字段仅为 `pair_id、pair_relation、pair_factor、constraint_checks、annotation_source`。

- `resume_label`：`resume / not_resume / censored / unknown`。
- `resume_step`：原目标合法步骤或 null；非空时 resume_label 必须为 resume。
- `window_complete`：布尔值。P1 中窗口未完整且未观察到恢复，不能作为已确认 not_resume 的负例；当前评测按删失排除并报告数量。窗口内已经观察到恢复的正例可以被识别。
- `state_labels`：按有证据的因素填写，缺乏依据可不提供、设 null 或使用合法 UNKNOWN；`state_evidence` 以相同因素键记录截至 cutoff 的 event_id 列表。非未知标注必须有证据。不得用未来行为反推 cutoff 的心理标签。
- `annotation_source`：可选来源说明；正式交接另附标注者、一致性、仲裁和版本记录，不能把这些信息写进 observation。

状态标签：

| 因素 | 合法标签 |
|---|---|
| V | `VALID / CANCELLED / FULFILLED / UNKNOWN` |
| F | `READY / BLOCKED / UNKNOWN` |
| A | `ACCESSED / NOT_ACCESSED / UNCERTAIN / UNKNOWN`；工程兼容 UNKNOWN，接触证据本身仍使用上节三值 |
| B | `BELIEVES_VALID / BELIEVES_INVALID / UNRESOLVED / UNKNOWN` |
| C | `ACTIVE / SUSPENDED / ABANDONED / COMPLETED / UNKNOWN` |
| Q | task_steps 中的步骤 ID，或 `UNKNOWN / NOT_APPLICABLE` |

当前 pair_relation 仅接受 `same_prediction / different_belief / same_mental` 或不提供；一个对照 pair_id 对应两个成员。B 如需新增“恢复步骤应改变”等关系，先与 C 扩展校验和指标，不能复用错误语义。`constraint_checks` 目前可提供 `known_cancelled: bool` 和 `forbidden_belief: 非空标签字符串`，必须由 B 根据可核查证据标注，不根据模型输出决定。

## 5. A 方预测接口

Python 模型接口约定：

```python
model.method_id
model.fit(train_pairs)       # 仅训练集 observation/gold 对；是否训练由各模型说明
model.predict(observation)  # 不接收 sample_id、gold、split 或未来轨迹
model.spec()                # 可序列化配置、版本、参数/预算与局限
model.availability()        # {"available": bool, "reason": str}
```

已训练外部模型也可提供命令形式：stdin 一个 observation JSON，stdout 一个 prediction JSON，日志写 stderr；当前 B10 命令接口不替 A 执行训练。A 应事先给出模型代码、环境、配置、检查点与训练记录。退出码非零、超时、非法 JSON 或非法分布是失败，不能拿占位答案补齐成功率。

规范输出字段至少包含：

```json
{
  "resume_label": "resume",
  "resume_step": "print",
  "p_resume": 0.6,
  "conditional_step_probs": {"pack": 0.1, "print": 0.8, "handover": 0.1},
  "state_probs": {"C": {"ACTIVE": 0.2, "SUSPENDED": 0.8}},
  "evidence_event_ids": [],
  "reason": "基于截止证据的简要说明；这里只是字段示例，不是实测预测",
  "metadata": {}
}
```

resume_label 仅为 `resume / not_resume`；not_resume 时 resume_step 必须为 null。恢复步骤未知时允许 null，但相应步骤评价不能算作答对。p_resume 必须为 `[0,1]` 有限数值或 null；conditional_step_probs 为合法步骤概率对象或 null；state_probs 仅填写模型真正提供的因素分布，缺失用 `{}`。每个非空分布必须有限、非负并和为 1；证据 ID 只能来自实际模型输入。不得把硬标签转换成伪造的 0/1“校准概率”。

metadata 记录实际模型/代码版本、概率来源、模型参数或检查点标识、调用次数、token usage、时延、种子与异常；不写密钥。不能提供的统计保留 null 并说明原因。原始 MENTIS 适配当前只提供硬标签，分支价值评分不等同于恢复概率。

外部随机种子必须另行披露能力：编排器把本轮编号写到顶层 `config.run_seed`；外部方法在 spec/metadata 中记录 `requested_seed`。默认 `supports_seed=false`，不把编号发送给上游，`seed_control=unsupported_repeat_only`，只表示重复运行。只有适配器和上游实际支持时才设置 true：HTTP 发送 seed 参数，命令设置 `MWM_SEED`；此时标记 `requested_not_verified`，也不保证供应商推断完全确定。当前官方 MENTIS 适配器未实现上游采样 seed 控制，应保持 false。A 的命令如声明支持，必须实际读取并应用 `MWM_SEED`，而不只是打印这个值。

失败不等于没有成本。外部响应的 token 账目保存在 `metadata.external.usage`；若解析或规范校验失败，则保存在 `ExternalPredictionError.metadata.usage`。命令非零退出或超时前已完整输出的 usage 也保留。HTTP 重试中已知 usage 累加，未知尝试不填零，并记录 `attempt_usage / n_usage_known_attempts / n_usage_unknown_attempts / usage_scope`。编排器须从异常提取这份账目，不能仅合计成功样本。

## 6. 三人交接验收

**B → C：** 两个 JSONL、分组划分清单、P0/P1 数据卡、许可和来源、标注手册与版本、事件语义映射、真实时间和预测窗口定义、删失规则、双人一致性与仲裁记录、最小对照关系和证据。P0 与 P1 分开交，不把自造样例包装成真实人类记录。

**A → C：** B10 与 A0–A7、§5.12 附加对照的真实实现/配置/检查点、训练数据 hash、训练种子、损失开关和权重、基座版本、参数数量、状态空间/粒子预算、训练算力及推理预算、启动命令和环境说明、输出协议示例、相同 observation 两次调用的随机性说明。`configs/ablation_matrix.json` 中 null 表示尚未交付。

**C → A/B：** 接口校验日志、每样例原始预测与错误、输入与配置 hash、完整运行 manifest、指标与覆盖率、成本、成对/跨域/压力结果、可重跑入口和明确的未完成状态。双方应先用小份真实交接样本通过协议检查，再跑全量研究实验。
