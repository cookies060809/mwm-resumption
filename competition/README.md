## 1. 赛题要求摘要

- 聚焦人工智能底层算法的原始创新与优化突破；本项目定位为**大模型与智能体、序列状态推断、概率化推理**。
- 提交材料需包含完整技术方案：问题定义、算法设计、数学推导、实验验证、真实实验数据及对比分析。
- 算法需经过测试验证，并提供开源代码或可复现的实验环境说明。
- 作品须原创、无知识产权争议；引用他人技术或数据必须明确标注并取得合法授权。
- 评分重点：算法模型创新性、技术先进性、科学价值与实际应用潜力。

官方评分表：

| 评分项 | 分值 | 评分要点 |
|---|---:|---|
| 创新性 | 20 | 全新架构或对经典算法的重大改进；局部优化得分较低 |
| 技术实现难度 | 20 | 算法设计复杂合理、采用前沿方法、实现难度高 |
| 实验验证 | 20 | 设计严谨、使用公开或实际数据、对比多个先进算法、结果可靠 |
| 方案完整性 | 20 | 项目概述、算法设计、实验验证等核心部分完整、逻辑清晰 |
| 应用价值 | 15 | 能解决实际问题，具备应用效果或明确落地潜力 |
| 总结与展望 | 5 | 总结精准、不足分析深入、改进方向明确 |

## 5. 当前优先级

1. **冻结算法故事**：确认 EC-JMF 的相对已有工作的差异点，避免“首次提出”类不可辩护表述。
2. **冻结并扩充评估协议**：P01–P08 种子已建；继续扩增、完成人工复核与盲审，并冻结 T1/T2 标签、基线与指标。
3. **实现最小闭环**：EC-JMF 最小版本 + B0–B7 基线，先在 P0 上跑通。
4. **形成证据链**：主实验、消融、校准、成本、逐样例失败分析。
5. **成稿与提交**：技术方案 PDF、答辩 PPT、3–5 分钟视频、佐证材料、代码链接。
6. **合规审查**：无学校/Logo/指导教师信息；无虚构数据；引用与数据许可完整。

## 6. 合规与公平性

- 所有提交材料（方案、视频、PPT）中不得出现参赛团队所在学校名称、Logo、指导教师等信息。
- 不得伪造、抄袭、代做或隐瞒数据来源；引用论文、代码、数据必须标注。
- P0 脚本结果只能写成受控协议诊断；没有 P1 真实行为数据时，不得声称“预测真实人类恢复”。
- 代码包需包含运行环境、依赖版本、随机种子、配置与复现命令。
- 提交前由 A/B/C 三人共同核对“已完成/已验证”措辞与所有数字。
