# T3 逐因子证据映射（B 侧规范）

> Owner：B。状态：B 侧已定稿，待 C 确认指标实现。对应 A 的 `A_INTERFACES.md` 中
> “T3 汇总映射待 B/C 确认”。适用数据：P0 v0.4（254 条）。
> 本文件只规定**金标准的证据口径**，不规定 A 可以在推理时读什么。

## 1. 权威字段

每条 P0 记录有两个证据字段：

| 字段 | 含义 | 谁可以用 |
|---|---|---|
| `state_evidence_by_factor.{V,F,A,B,C,Q}` | 该因子判定的逐因子证据事件 ID 列表 | **评测/审计侧**；不得进入模型输入 |
| `state_evidence_event_ids` | 上述逐因子证据按事件顺序去重后的并集 | 同上 |

- 非 `UNKNOWN` 的因子必须至少有一条证据（v0.4 实测：V/F/A/B/C/Q 的 253/253/254/250/253/254 条全部有证据）。
- 证据 ID 必须出现在 `observed_events` 内，且不得晚于 `cutoff_event_id`。
- 因子为 `UNKNOWN` 时证据为空；**空证据 + 非 UNKNOWN 视为数据错误**，由 `validate_data.py` 拦截。

## 2. 逐因子证据规则

| 因子 | 手册 | 什么算证据 | 什么不算 |
|---|---|---|---|
| V | §2.2 | 客观取消/完成/有效的世界记录，或明确的无取消状态起点 | 人物陈述；`B` 的取值 |
| F | §2.3 | 资源/权限/工具的明确就绪或缺失证据 | 由“前一步完成”推出后续资源就绪 |
| A | §2.4 | 人物直接执行、明确看到/听到通知、投递日志 + 可感知证据 | 世界事实本身；通知已发送但未见/未听 |
| B | §2.5 | 人物自述、明确的继续/无效表达、人物可获得的冲突通知 | 从 `V` 复制；从 `C` 反推；单纯返回动作 |
| C | §2.6 | 完成/放弃陈述、持续推进、明确的继续意图；显式放弃优先于其后一般步骤动作 | 仅由 `B` 推出；把取消通知当成人物放弃 |
| Q | §2.7 | 人物主观进度证据（自述剩余步骤、明确的步骤记忆） | 客观完成快照；未来步骤 |

## 3. 给 A 的映射

A 当前用“按输入选出的最近显著事件”近似关键事件。B 的对接口径：

1. **输入侧**：A 仍只读 `observed_events`，**不得**读 `state_evidence_by_factor`、`state_evidence_event_ids` 或任何 gold 证据字段。
2. **输出侧**：A 的 `prediction.evidence_event_ids` 是它自己引用的证据集合，可以与 B 的逐因子证据比较，但比较结果是**诊断指标**，不是“A 复现了 B 的标注规则”。
3. **逐因子对齐**：若要做 T3 证据一致性，按因子分别计算 A 引用集合与 `state_evidence_by_factor[f]` 的命中/覆盖；不要把六个因子的证据并集当成一个集合算单指标。
4. **不匹配的合法情形**：同一因子可以有多条等价证据（如 A 的 `ACCESSED` 可由直接执行或通知确认支撑），A 只引用其中一条不算错；反之，引用与标签无关的事件计入误报。

## 4. 给 C 的映射

- 评测 T3 时，以 `state_evidence_by_factor` 为唯一金标准证据源；`state_evidence_event_ids` 只用于快速检查“证据是否都落在输入内”。
- 证据一致性指标建议分别报告：逐因子 precision/recall/覆盖、以及“引用了 cutoff 之后事件”的硬错误数（应为 0）。
- 证据 ID 的集合比较必须忽略顺序；同一事件可以同时是多个因子的证据。

## 5. B 不做的声明

- 不声称 A 的“最近显著事件”能自动复现 B 的标注规则。
- 不把证据一致性当作状态准确率的替代；二者分开报告。
- 不在 P1 public_derived 上使用该映射：P1 的六因子规则映射值已按 `state_withdrawn` 撤回，只剩 V 带证据。
- `comprehension`（U）的事件级证据在 P0 v0.2+ 已结构化，但不在本文件的六因子范围内；需要时另立映射。
