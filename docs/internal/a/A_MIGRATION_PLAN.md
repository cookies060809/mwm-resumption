日期：2026-10-20。初步依据为实际目录/Git/协作规则读取；六轮检查完成前不修改共享仓库。

## 初始完整方案

1. 独立查验共享仓库三次，每次重查 Git 状态、分支/远程、完整文件清单、协作规则、接口/schema、实际 P0 和本地 A 产物；记录树/关键文件哈希及差异。远程 tip 用只读查询，之后再 fetch 创建分支。
2. 各自独立审视整份迁移方案三次，不按主题分工：事实、范围、协作、schema/接口、P0诊断、风险和结论边界都必须覆盖。整合全部发现，核对分歧后才落地。
3. 共享 main 需保持干净。从 fetch 后最新适合的 origin/main 创建独有 `feat/a-ec-jmf-p0-adapter`（若已存在先核查，不覆盖）。不进入 Bill/qiqi 分支；不合并远程成员分支、不更改 B schema/数据。
4. 必迁 A 接口：适配共享 schema 词表与 HH:MM；不引入本地 provisional schema 为共享标准。迁移通用概率内核与配置、正式算法/风险决策；本地 contracts 仅选择可用 helper。保留现有 README 契约并说明低层与公共接口的层次，不伪称 M1 已冻结。
5. 不迁移 A 玩具转移、合成夹具、本地 tests、诊断脚本/JSON、生成结果、原始计划副本。A 源目录只读保留。可在共享分支新增针对实际 P0 的正式契约回归检查，不复制本地测试文件。
6. 先实测 P0 数量/格式/版本/标签/审计与 P1 状态，再确定诊断。白名单只读取历史事件和图/目标/窗口等合法输入；从输入对象剔除 notes/annotation/state labels/policy/expected/P1 fields/样本变体标识，禁止偷读答案。人物视图不得透传混合 description/world_effect；接触与理解分离，原始记录不足的语义标明限制。
7. 对实际 P0 完成 schema/跨字段校验、适配读取、时间截断/图/引用检查、人物与世界通道检查、P07 输入一致性和禁用字段扰动不变性、客观与主观进度分离检查。仅在有合理已实现语义模型时运行预测；否则明确诊断为输入可用性/隔离/推断核集成，不制造准确率或玩具认知规则。记录未支持功能与所需 B/C 后续输入。
8. 运行仓库现有 validator、pair diff、pytest，加实际P0契约检查；不运行会覆盖数据的 build_p0_seed。检查 diff、隐私/密钥与禁止迁移材料，产出可复现命令和有依据的内部报告。生成原始输出不入 Git；报告记录运行命令、数据哈希和基线版本。
9. 按 Conventional Commits 提交，推送 A 自己远程分支，无 force/main merge。团队成员评审留到后续合并流程；本次不冒充 B/C 人工审签。若权限/认证拒绝如实报告，不绕过。
